# Stremio Live TV

Your private M3U playlists in **Discover → Live TV → playlist name → channels**.

Each playlist becomes its own Discover list. Required catalog filters keep the add-on off Home. The service rejects movies, series, recordings and ambiguous entries rather than importing your IPTV VOD library.

**[Read the illustrated setup guide](https://dev1niscool.github.io/stremio-live-tv/)** · **[Deploy on Render](https://render.com/deploy?repo=https://github.com/dev1niscool/stremio-live-tv)**

## Host your own on Render Free

1. Fork this repository into your GitHub account, or deploy the original if you do not need your own source copy.
2. In [Render](https://dashboard.render.com/), choose **New → Web Service → Public Git Repository** and enter your repository URL. Choose **Node**, the **Free** instance, build command `node --check src/server.mjs`, and start command `node src/server.mjs`. Add `NODE_VERSION=24`. No database or paid disk is needed.
3. Deploy. Open the resulting `https://YOUR-SERVICE.onrender.com` URL. The empty service shows a setup form.
4. Give every M3U playlist a name and paste its private URL. Click **Generate private settings**. These links stay in your browser; the page does not upload or persist them.
5. In Render, open the service’s **Environment** settings. Add `PLAYLISTS_JSON` and `ADDON_TOKEN` using the two values generated by the form. Select **Save, rebuild, and deploy**. Save your access key in a password manager.
6. Return to the service, enter that key, and check your playlist counts. Click **Install in Stremio**, or copy the manifest URL into Stremio’s **Add-ons** screen. Open **Discover → Live TV**, then choose a playlist.

The included `render.yaml` also supports Blueprint deployment. It creates only a Free service, generates an access key and prompts for `PLAYLISTS_JSON`. Use `[]` initially, then complete the setup form. The generated key can be viewed in Render’s Environment settings, or replaced with the setup form’s generated key before installing.

**Free hosting limitations:** Render sleeps after 15 minutes idle and can take about a minute to wake. Open your service URL before opening Discover if necessary. It provides 750 free instance-hours per workspace per month, with bandwidth/build limits. Without a payment method, exhausted allowances suspend free services instead of billing overages. Do not add a paid instance, database, disk, or payment method if you want a strictly free setup. Some accounts may encounter a verification requirement. See [Render’s current free plan](https://render.com/docs/free). The service downloads playlists and returns direct playback URLs; it does **not** relay video through Render.

## Private configuration

Never put your real M3U URLs, provider credentials, `.env`, access key or installed manifest URL in GitHub, issues, screenshots, or the public guide. Use **private environment values** on your host. A public source repository is fine: it contains no playlist credentials. The host itself receives the M3U credentials to fetch playlists, and Stremio receives playback URLs when you watch.

`ADDON_TOKEN` protects the manifest, channel metadata, stream responses, and diagnostics. Anyone with the tokenized install link can use the add-on and retrieve provider stream credentials. Treat it as a password. Rotate the key and reinstall the add-on if exposed. The public root page and `/health` expose no playlists. There is no telemetry, analytics, database, or browser storage.

`PLAYLISTS_JSON` example (fictional placeholders):

```json
[
  {
    "id": "provider-one",
    "name": "My provider",
    "url": "https://provider.example/get.php?username=YOUR_USER&password=YOUR_PASSWORD&type=m3u_plus&output=ts",
    "includeGroups": [],
    "excludeGroups": []
  },
  {
    "id": "provider-two",
    "name": "Second provider",
    "url": "https://second.example/playlist.m3u",
    "includeGroups": ["US | Entertainment", "UK | Sports"],
    "excludeGroups": []
  }
]
```

Up to 50 sources. Keep each `id` stable when changing URLs. The setup form generates stable IDs from playlist names; changing the name creates a new catalog identity. Optional playlist request `headers` support `User-Agent`, `Referer`, `Authorization`, and `Accept`. Playback headers in M3U entries support `User-Agent`, `Referer`, and `Origin` via pipe URL suffixes or `#EXTVLCOPT`; other provider-specific header formats are not implemented.

| Variable | Purpose |
| --- | --- |
| `PLAYLISTS_JSON` | Private JSON array of named playlist sources; defaults to `[]` |
| `ADDON_TOKEN` | Private URL-safe access key, 32–256 characters |
| `NODE_VERSION` | Set to `24` on Render |
| `PUBLIC_URL` | Optional public HTTP(S) origin; Render’s external URL is detected automatically |
| `CACHE_TTL_SECONDS` | Playlist refresh interval, default `900`; allowed 60–86400 |
| `PORT` | Host-provided port; defaults to 7860 locally |

To update a source, edit `PLAYLISTS_JSON` and redeploy, keeping `ADDON_TOKEN` unchanged. Adding/removing/renaming sources changes the manifest: reinstall the add-on if Stremio keeps the old list. Changing stream credentials does not require reinstalling when the source ID and key remain the same.

## How live-only filtering works

The parser first rejects positive durations, VOD/movie/series paths and formats, VOD metadata/groups, episode-style titles, and catch-up/recording entries. It then requires a live signal in the path, metadata, query, or group. A duration of `-1` or `0`, a channel ID, or `.m3u8`/`.ts` alone does **not** prove a stream is live.

If legitimate channels are missing, enter their **exact group names** under **Live channel filtering → Confirmed live groups**. That list both confirms live intent and limits the source to those groups. Use `Ungrouped` for channels with no group. Strong VOD signals still take precedence. `excludeGroups` always wins. Conservative filtering can also exclude genuine movie-channel groups with VOD-like names.

M3U has no universal, trustworthy live/VOD flag. A provider that mislabels VOD as live cannot be detected perfectly without validating the media itself. Inspect the accepted counts/groups with your actual provider. No channel streams are opened while indexing. HLS media/master manifests cannot be used as channel-list sources.

## Local development and Docker

Requires Node.js 24 or newer. No third-party runtime dependencies or install step.

```sh
git clone https://github.com/dev1niscool/stremio-live-tv.git
cd stremio-live-tv
cp .env.example .env
# Start the setup page first; then put generated settings into .env and restart.
npm start
```

Open `http://localhost:7860`. Put the JSON on one line in `.env`, quoted with single quotes if needed. For a production remote add-on, use an HTTPS host accessible by your Stremio devices.

```sh
npm test
npm run check
docker build -t stremio-live-tv .
docker run --rm --env-file .env -p 7860:7860 stremio-live-tv
```

The Dockerfile can run on another container host. Hugging Face is no longer the recommended free path: its current policy requires a paid plan to create Docker Spaces, despite CPU Basic having no hourly charge. Fly.io offers a limited trial rather than an ongoing free tier. ## Protocol and troubleshooting

- Catalogs use custom type `Live TV`, with required `genre=All channels`. Stremio’s Home request lacks that filter, so these catalogs do not qualify for Home. The server also returns no results if it is absent. Discover initializes it to `All channels`.
- Metadata uses `isLive: true` and `defaultVideoId`. Catalog pages contain up to 100 channels. IDs are scoped to each playlist; entries with a stable `tvg-id`, name and group survive rotating URL credentials.
- Custom types work in current Stremio core/web; exact rendering across every TV/mobile client is not verified. Try the current desktop app if a client hides custom types. These catalogs deliberately do not participate in global search.
- Playback happens directly in your Stremio player. Browser CORS, codecs, HTTP streams, geo/IP restrictions, provider connection limits and playback headers can affect compatibility. Desktop/Android TV or an appropriate external player may be needed. This service does not transcode or bypass provider restrictions.
- An unreachable playlist does not prevent other sources from working. Authenticated status shows its error without disclosing its URL. Failed sources are not served stale. Public/private-network URL checks, bounded downloads, redirect validation, a total fetch timeout and a bounded memory cache protect the host.
- If no channels appear, check the excluded counts and configure exact live groups. If install fails immediately after idle, wake the Render URL, wait a minute, then retry. If a provider works locally but not on Render, it may restrict datacenter IPs.

## Publish your own guide

The `docs/` directory is the GitHub Pages tutorial. In your fork, enable **Settings → Pages → Source → GitHub Actions**, then run the **Publish guide** workflow. Update the repository URLs in the guide and setup page to point to your fork. Pages only hosts the guide; the add-on API must run on Render or another backend host.
