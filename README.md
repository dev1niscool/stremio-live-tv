# Stremio Live TV

Your private M3U playlists in **Discover → Live TV → playlist name → channels**, with an additional native TV programme guide on compatible Stremio clients.

Each playlist keeps its original Discover list. Sources with XMLTV also supply Stremio's native `tv`/EPG protocol. Required catalog filters keep channel rows off Home. The service excludes IPTV movies, series, recordings and ambiguous entries; programme listings describe broadcasts on accepted live channels and never create VOD catalogs.

**[Read the illustrated setup guide](https://dev1niscool.github.io/stremio-live-tv/)** · **[Deploy on Render](https://render.com/deploy?repo=https://github.com/dev1niscool/stremio-live-tv)**

## Host your own on Render Free

1. Fork this repository into your GitHub account, or deploy the original if you do not need your own source copy.
2. In [Render](https://dashboard.render.com/), choose **New → Web Service → Public Git Repository** and enter your repository URL. Choose **Node**, the **Free** instance, build command `npm ci --ignore-scripts && node --check src/server.mjs`, and start command `node src/server.mjs`. Add `NODE_VERSION=24`. No database or paid disk is needed.
3. Deploy. Open the resulting `https://YOUR-SERVICE.onrender.com` URL. The empty service shows a setup form.
4. Import a local text file, paste notes containing M3U links, or add URLs individually. Review the extracted sources. Account list names default to the URL's exact decoded **username**, preserving spelling and case; you can override them. Generic lists default to a hostname or an imported Markdown label. Click **Generate private settings**. The importer runs entirely in your browser and does not upload or persist the text or links.
5. In Render, open the service’s **Environment** settings. Add `PLAYLISTS_JSON` and `ADDON_TOKEN` using the two values generated by the form. Select **Save, rebuild, and deploy**. Save your access key in a password manager.
6. Return to the service, enter that key, and check your playlist and programme-guide counts. Click **Install in Stremio**, or copy the manifest URL into Stremio’s **Add-ons** screen. Open **Discover → Live TV**, then choose a playlist. Compatible clients also display native TV guides for sources with XMLTV configured.

The included `render.yaml` also supports Blueprint deployment. It creates only a Free service, generates an access key and prompts for `PLAYLISTS_JSON`. Use `[]` initially, then complete the setup form. The generated key can be viewed in Render’s Environment settings, or replaced with the setup form’s generated key before installing.

**Free hosting limitations:** Render sleeps after 15 minutes without inbound requests and can take about a minute to wake. Its 750 monthly free instance-hours are shared across a workspace. Bandwidth and build allowances also apply: without a payment method, exceeding them suspends free services or stops new builds, depending on the allowance. Keep the service on Free; no paid disk, database, or payment method is needed by this project. Some accounts may require verification. See [Render’s current free plan](https://render.com/docs/free). Playback URLs point directly to your provider; this service does **not** relay video through Render.

### Keep the service ready while watching

Use **Wake now** on your service page or the guide's **[existing-host tab](https://dev1niscool.github.io/stremio-live-tv/#ready)**. Enter only the public service origin, such as `https://YOUR-SERVICE.onrender.com`; no access key is needed for the health check.

**Keep awake while watching** starts a finite browser session of 1, 2, 4, or 8 hours. It requests `/health` approximately every four minutes and stops when the session expires, you press **Stop**, or you leave the page. Keep the browser and device running: suspended tabs, device sleep and lost connectivity can interrupt checks. This is not a guarantee of continuous hosting, and it uses your normal Render running-hour allowance. There is no server self-ping or background scheduler. A direct IPTV stream usually continues if the add-on service sleeps; loading another channel or refreshing its guide may need the service to wake again.

## Private configuration

Never put your real M3U/XMLTV URLs, provider credentials, `.env`, access key or installed manifest URL in GitHub, issues, screenshots, or public messages. Use **private environment values** on your host. A public source repository is fine: it contains no playlist credentials. The host receives the credentials needed to fetch playlists and guides; Stremio receives playback URLs when you watch. Default list titles contain account usernames, so avoid sharing screenshots of those titles if the usernames are sensitive.

`ADDON_TOKEN` protects the manifest, channel metadata, stream responses, and diagnostics. Anyone with the tokenized install link can use the add-on and retrieve provider stream credentials. Treat it as a password. Rotate the key and reinstall the add-on if exposed. The public root page and `/health` expose no playlists. There is no telemetry, analytics, database, or browser storage.

`PLAYLISTS_JSON` example (fictional placeholders):

```json
[
  {
    "id": "provider-one",
    "name": "ExampleUser",
    "url": "https://provider.example/get.php?username=ExampleUser&password=YOUR_PASSWORD&type=m3u_plus&output=ts",
    "includeGroups": [],
    "excludeGroups": []
  },
  {
    "id": "provider-two",
    "name": "Second provider",
    "url": "https://second.example/playlist.m3u",
    "epgUrl": "https://second.example/guide.xml",
    "includeGroups": ["US | Entertainment", "UK | Sports"],
    "excludeGroups": []
  }
]
```

Up to 50 sources. Keep each `id` stable when changing URLs or display names. The importer derives account identities independently of their display names and removes repeated Xtream accounts, keeping the first URL it finds. Review duplicates when credentials have changed. Generic signed/tokenized URLs can represent different playlists and are kept separate. If you hand-write JSON and omit `name`, the server uses the URL's `username`, then its hostname; supplying explicit stable IDs avoids collisions between accounts with the same display name.

The local importer accepts text files and pasted notes, including Markdown links and common escaped URL forms. It recognizes Xtream `get.php` links and M3U channel-list URLs; unsupported links can be entered individually. It does not contact providers to validate extracted links. Review its output before copying: trailing punctuation in prose can be ambiguous, so percent-encode punctuation that is part of a credential. Files totaling up to 5 MiB can be processed locally.

Optional playlist request `headers` support `User-Agent`, `Referer`, `Authorization`, and `Accept`. Playback headers in M3U entries support `User-Agent`, `Referer`, and `Origin` via pipe URL suffixes or `#EXTVLCOPT`; other provider-specific header formats are not implemented.

| Variable | Purpose |
| --- | --- |
| `PLAYLISTS_JSON` | Private JSON array of named playlist sources; defaults to `[]` |
| `ADDON_TOKEN` | Private URL-safe access key, 32–256 characters |
| `NODE_VERSION` | Set to `24` on Render |
| `PUBLIC_URL` | Optional public HTTP(S) origin; Render’s external URL is detected automatically |
| `CACHE_TTL_SECONDS` | Playlist refresh interval, default `900`; allowed 60–86400 |
| `PORT` | Host-provided port; defaults to 7860 locally |

To update a source, edit `PLAYLISTS_JSON` and redeploy, keeping `ADDON_TOKEN` unchanged. Adding/removing/renaming sources changes the manifest: reinstall the add-on if Stremio keeps the old list. Changing stream credentials does not require reinstalling when the source ID and key remain the same.

## Real programme guides, alongside the original channel lists

The classic **Discover → Live TV** list remains available for every source. When a source has an XMLTV URL, the manifest additionally exposes a native `tv` catalog and marks the add-on as an EPG provider. Clients implementing Stremio's native TV guide can request daily schedules. Native guide availability and presentation depend on the client/version; use the classic list when your client does not support it.

Set the optional `epgUrl` field per playlist:

| Value | Behaviour |
| --- | --- |
| Omitted or empty | For a Xtream `get.php` URL with `username` and `password`, derive the sibling `xmltv.php` endpoint with those credentials; other source URLs need an explicit guide URL |
| An HTTP(S) XMLTV URL | Use that guide instead of the derived endpoint |
| `false` | Disable XMLTV and the additional native guide for this source |

The setup form exposes these options under **Programme guide**. A provider may use a different XMLTV endpoint or offer no EPG; automatic derivation does not guarantee a working guide. Plain XML, HTTP-compressed responses, and gzip XML files are supported within the download/decompression limits. Do not use a single HLS playback manifest as a guide.

Programme `channel` values must exactly match accepted live channels' M3U `tvg-id` values. Matching is case-sensitive and does not guess from channel names. The guide retains actual programmes from the previous UTC day through seven days ahead, including programmes crossing midnight. Missing titles, invalid dates and missing/reversed end times are skipped; missing schedules stay empty. Numeric timezone offsets are respected and timestamps without a timezone are treated as UTC. External XMLTV DOCTYPE declarations are never downloaded; internal subsets and custom entities are rejected.

Guide failures leave the classic live channel list usable. The status view reports whether a guide is unavailable, empty, or has matched programmes. There are no fabricated schedules, VOD imports, recordings or catch-up playback. Reinstall after upgrading an existing add-on so Stremio receives the new native guide catalogs.

## How live-only filtering works

The parser first rejects positive durations, VOD/movie/series paths and formats, VOD metadata/groups, episode-style titles, and catch-up/recording entries. It then requires a live signal in the path, metadata, query, or group. A duration of `-1` or `0`, a channel ID, or `.m3u8`/`.ts` alone does **not** prove a stream is live.

If legitimate channels are missing, enter their **exact group names** under **Live channel filtering → Confirmed live groups**. That list both confirms live intent and limits the source to those groups. Use `Ungrouped` for channels with no group. Strong VOD signals still take precedence. `excludeGroups` always wins. Conservative filtering can also exclude genuine movie-channel groups with VOD-like names.

M3U has no universal, trustworthy live/VOD flag. A provider that mislabels VOD as live cannot be detected perfectly without validating the media itself. Inspect the accepted counts/groups with your actual provider. No channel streams are opened while indexing. HLS media/master manifests cannot be used as channel-list sources.

## Local development and Docker

Requires Node.js 24 or newer. Install the locked dependencies (`saxes` and its XML character helper) before starting the service.

```sh
git clone https://github.com/dev1niscool/stremio-live-tv.git
cd stremio-live-tv
npm ci --ignore-scripts
cp .env.example .env
# Start the setup page first; then put generated settings into .env and restart.
npm start
```

Open `http://localhost:7860`. Put the JSON on one line in `.env`, quoted with single quotes if needed. For a production remote add-on, use an HTTPS host accessible by your Stremio devices.

```sh
npm test
npm run check
docker build -t stremio-live-tv .
docker run --rm --env-file .env.docker -p 7860:7860 stremio-live-tv
```

For Docker, create an ignored `.env.docker` file with `KEY=value` lines. Keep `PLAYLISTS_JSON` on one line **without surrounding single or double quotes**: Docker preserves those quotes, whereas Node's `.env` parser removes them. Set `ADDON_TOKEN`, `PLAYLISTS_JSON`, and optionally `PUBLIC_URL` in that file. For a local container, leave `PORT` unset so the `7860:7860` mapping matches.

The Dockerfile can run on another container host. Hugging Face is no longer the recommended free path: its current policy requires a paid plan to create Docker Spaces, despite CPU Basic having no hourly charge. Fly.io offers a limited trial rather than an ongoing free tier. [Hugging Face policy](https://huggingface.co/docs/hub/spaces-overview#creating-a-new-space) · [Fly.io policy](https://fly.io/docs/about/cost-management/).

## Protocol and troubleshooting

- The original catalogs use custom type `Live TV`; additional XMLTV catalogs use native type `tv`. Both require `genre=All channels` for ordinary browsing. Home requests without the required filter return no channel rows. Native guide clients can use the `date=YYYY-MM-DD` EPG request path.
- Metadata uses `isLive: true` and `defaultVideoId`. Catalog pages contain up to 100 channels. IDs are scoped to each playlist; entries with a stable `tvg-id`, name and group survive rotating URL credentials.
- Exact guide rendering across every desktop/web/TV/mobile version is not verified. The original Discover lists remain as a fallback; these catalogs deliberately do not participate in global search.
- Playback happens directly in your Stremio player. Browser CORS, codecs, HTTP streams, geo/IP restrictions, provider connection limits and playback headers can affect compatibility. Desktop/Android TV or an appropriate external player may be needed. This service does not transcode or bypass provider restrictions.
- An unreachable playlist does not prevent other sources from working. Authenticated status shows its error without disclosing its URL. Failed sources are not served stale. Public/private-network URL checks, bounded downloads, redirect validation, a total fetch timeout and a bounded memory cache protect the host.
- If no channels appear, check the excluded counts and configure exact live groups. If install fails immediately after idle, wake the Render URL, wait a minute, then retry. If a provider works locally but not on Render, it may restrict datacenter IPs.
- If a native guide has no programmes, check its XMLTV URL and exact channel IDs. Seeing a live channel without a schedule does not mean playback is unavailable. Playlist and guide downloads each have a 20-second fetch timeout and a 25 MiB size limit; large provider-wide guides may need a smaller provider-supported feed.

## Publish your own guide

The `docs/` directory is the GitHub Pages tutorial. After editing shared tools in `public/` or `docs/guide-style.css`, run `npm run sync-docs` to update its bundled scripts and styles; CI checks these copies. In your fork, enable **Settings → Pages → Source → GitHub Actions**, then run the **Publish guide** workflow. Update the repository URLs in the guide and setup page to point to your fork. Pages only hosts the guide; the add-on API must run on Render or another backend host.
